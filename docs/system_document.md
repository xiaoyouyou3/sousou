# システム詳細設計書 (AI-Optimized)

## 1. 共通事項 (Global Definitions)

### 1.1 全体仕様

-   **ターゲットプラットフォーム:** モバイルアプリケーション (iOS / Android)
-   **基本ナビゲーション:** ログイン画面以外は、下部タブバーまたはドロワーによる画面遷移を想定（※要件定義書に基づき適宜補完）
-   **オーディオ仕様:** 端末のマナーモード（消音）設定に従い、ミュート時は音声を出力しない。

### 1.2 パスワードポリシー

-   **許可文字:** 半角英数字、および記号 (`@`, `*`, `-`, `+`, `!`, `?`, `#`, `$`, `%`, `&`, `￥`) のみ。
-   **最小/最大文字数:** (AI補完推奨: 例: 8文字以上、32文字以内)

## 2. 画面別仕様 (Screen Specifications)

### S-01: ログイン画面 (Login Screen)

#### 2.1 概要

ユーザーの認証（新規登録・ログイン）を行うエントリーポイント。

#### 2.2 UIコンポーネント

-   **タブ/切替スイッチ:** 「新規登録」と「サインイン」の表示切り替え
-   **新規登録フォーム (Sign Up View)**
    -   `Input_Email`: メールアドレス入力欄
    -   `Input_Password`: パスワード入力欄
    -   `Input_PasswordConfirm`: パスワード再入力欄
    -   `Btn_SignUp`: 新規登録実行ボタン
-   **サインインフォーム (Sign In View)**
    -   `Input_Email`: メールアドレス入力欄
    -   `Input_Password`: パスワード入力欄
    -   `Btn_SignIn`: サインイン実行ボタン

#### 2.3 ロジック & 振る舞い

-   **バリデーション:**
    -   メールアドレス形式チェック。
    -   パスワードポリシーチェック（許可文字種と文字数）。
    -   新規登録時、`Input_Password` と `Input_PasswordConfirm` が一致するか。
-   **`Btn_SignUp`押下時:**
    -   バリデーションOKなら、バックエンドへ登録リクエスト送信。
    -   成功時: ホーム画面(S-02)へ遷移。
-   **`Btn_SignIn`押下時:**
    -   認証リクエスト送信。
    -   成功時: ホーム画面(S-02)へ遷移。

### S-02: ホーム画面 (Home Feed Screen)

#### 2.1 概要

他ユーザーが作成した楽曲をフィード形式（TikTok/Reels風の縦スクロール想定）で視聴する画面。

#### 2.2 UIコンポーネント（イメージはApple Music）

-   `Main_View`: 楽曲再生エリア（全画面またはカード型）
-   `Effect_Layer`: 感情に合わせたエフェクト表示レイヤー（動画/アニメーション）
-   **`Action_Bar` (下部配置)**
    -   `Btn_PlayPause`: 再生/一時停止トグルボタン
    -   `Btn_Like`: いいねボタン（トグル）
    -   `Btn_Loop`: ループ再生ON/OFFトグルボタン

#### 2.3 ロジック & 振る舞い

-   **初期表示:** 最新またはおすすめの楽曲をロードし、自動再生開始（端末が消音モードでない場合）。
-   **ジェスチャー操作:**
    -   上スワイプ: 次の曲へ遷移。
    -   下スワイプ: 前の曲へ戻る。
-   **再生制御 (`Btn_PlayPause`):**
    -   再生中: ボタンアイコンを「一時停止」表示 → 曲を一時停止。
    -   停止中: ボタンアイコンを「再生」表示 → 曲を再開。
-   **ループ制御 (`Btn_Loop`):**
    -   OFF (Default): 曲終了時、自動的に「次の曲」へ遷移し再生開始。
    -   ON: 曲終了時、現在の曲の先頭に戻り再生を継続。
    -   UI状態: ON/OFFが視覚的に区別できること（色変化など）。
-   **いいね (`Btn_Like`):**
    -   タップでON/OFF切り替え。サーバーへ状態を同期。UIの色を変化させる。
-   **エフェクト:** 再生中の曲に紐づくメタデータ（感情タグ）に基づき、適切な視覚エフェクトを表示する。

### S-03: 曲作成画面 (Create Song Screen)

#### 3.1 概要

ユーザーがパラメータを指定し、AIを用いて楽曲を生成する画面。

#### 3.2 UIコンポーネント

-   `Select_Emotion`: 感情選択（ラジオボタンまたはチップ）
    -   選択肢: {喜び, 怒り, 悲しみ, 驚き, 恐れ, 嫌悪, 愛情}
-   `Select_Genre`: ジャンル選択（ドロップダウンまたはピッカー）
    -   選択肢: {邦ロック, レゲエ, ...他, おまかせ}
-   `Select_Duration`: 曲の長さ選択
    -   選択肢: {短め(25~35秒), 長め(80~100秒)}
-   `Input_Prompt`: プロンプト入力テキストエリア（自由記述）
-   `Btn_RefinePrompt`: 「AI修正」ボタン
-   `Btn_Create`: 「曲作成」実行ボタン

#### 3.3 ロジック & 振る舞い

-   **ジャンル「おまかせ」ロジック:**
    -   `Select_Genre` で「おまかせ」が選択された場合、`Select_Emotion` の値と `Input_Prompt` の内容を解析し、LLMが最適なジャンルを自動決定する。
-   **プロンプト修正 (`Btn_RefinePrompt`):**
    -   `Input_Prompt` の内容をLLM APIに送信し、音楽生成AIに適したプロンプトに変換して入力欄に反映する。
-   **作成実行 (`Btn_Create`):**
    -   全パラメータを生成APIに送信。
    -   生成中はローディング表示を行う。
    -   生成完了後、プレビューまたはユーザー画面(S-04)への遷移を行う。

### S-04: ユーザー画面 (User Profile Screen)

#### 4.1 概要

自身が作成した楽曲の管理・視聴画面。

#### 4.2 UIコンポーネント

-   `Grid_View`: 作成した曲のサムネイル一覧
    -   各アイテム: タイトル、再生ボタン
-   `Detail_Modal` / `Detail_View`: 個別曲の再生画面（Grid内の再生ボタン押下で遷移）
    -   UIはホーム画面(S-02)をベースにするが、下部コントロールが異なる。
    -   `Btn_PlayPause`: 再生/一時停止
    -   `Btn_Continuous`: 連続再生ON/OFFボタン

#### 4.3 ロジック & 振る舞い

-   **遷移:** Grid内の再生ボタン押下で、対象の曲をメインとした再生モードへ遷移。
-   **連続再生制御 (`Btn_Continuous`):**
    -   OFF (Default): 曲終了時、同じ曲をループ再生する。
    -   ON: 曲終了時、Grid順における次の曲へ自動遷移し再生する。
    -   UI状態: ON/OFFが視覚的に区別できること。

### S-05: 設定画面 (Settings Screen)

#### 5.1 概要

アカウント情報およびアプリ設定の変更を行う画面。

#### 5.2 UIコンポーネント

-   **`Area_ChangeEmail`:** メールアドレス変更エリア
    -   `Input_NewEmail`: 新しいメールアドレス
    -   `Input_NewEmailConfirm`: 確認用入力
    -   `Btn_UpdateEmail`: 変更実行ボタン
-   **`Area_ChangePassword`:** パスワード変更エリア
    -   `Input_CurrentPassword`: 現在のパスワード
    -   `Input_NewPassword`: 新しいパスワード
    -   `Input_NewPasswordConfirm`: 確認用入力
    -   `Btn_UpdatePassword`: 変更実行ボタン
-   **`Area_ThemeSettings`:** 画面テーマ設定エリア
    -   `Switch_DarkMode`: ダークモードON/OFF切り替えスイッチ

#### 5.3 ロジック & 振る舞い

-   **メール変更:** 入力一致確認後、更新APIを実行。
-   **パスワード変更:**
    -   現在のパスワードの照合（API側または事前チェック）。
    -   新しいパスワードのポリシーチェック（S-01同様）。
    -   新しいパスワードと確認用の一致チェック。
    -   全てOKなら更新APIを実行。
-   **テーマ変更 (`Switch_DarkMode`):**
    -   ON: アプリ全体の配色をダークブルー基調のテーマ（Dark Theme）に切り替える。
    -   OFF: デフォルト（ライト/通常）テーマを適用する。
    -   設定値はローカルストレージに保存し、アプリ再起動時も設定を維持する。

## 2. 技術スタック定義書 (Tech Stack Definition)
本システムは、モバイルアプリケーション、Web API、およびAIモデル実行環境の3層構造で構築されます。インフラストラクチャ層には主にFirebase Studioの各種ツールを使用します。
### 1.1 フロントエンド (Frontend / Client)
| 項目 | 技術名 | 目的・選定理由 |
| :--- | :--- | :--- |
| フレームワーク | Flutter (Dart) | iOS/Androidの両プラットフォームに高品質なUIを単一コードベースで提供するため。カスタムUI、特にエフェクトや没入感のあるデザイン（UIデザインガイドライン参照）の実現に適している。 |
| 状態管理 | riverpod または Provider | Flutterのリアクティブな状態管理を実現し、UIテーマ（ダークモード）の切り替えやフィードデータの更新を効率的に行うため。 |
| UIデザイン | カスタム/パッケージ | ダークブルー基調のモダンデザインを実装するため、テーマ設定、Glassmorphism効果などを活用する。 |
| オーディオ | just_audio など | 楽曲の再生、ループ再生、バックグラウンド再生を安定して行うためのライブラリ。 |
| Firebase連携 | firebase_core, firebase_auth, cloud_firestore, firebase_storage | 各Firebaseサービスとの統合およびリアルタイム性の確保。 |

### 1.2 バックエンド (Backend / API Server)
バックエンドは、AI生成処理のハブ、および高度なデータ処理（レコメンドロジック、データ分析）を担います。基本的な認証・データ永続化はFirebaseにオフロードします。
| 項目 | 技術名 | 目的・選定理由 |
| :--- | :--- | :--- |
| 言語 | Python | AI・機械学習領域の処理、特に音楽生成AIモデルとの連携に最適であるため。 |
| フレームワーク | FastAPI | 選定理由: ユーザーリクエストが長時間かかるAI処理（非同期処理）を伴うため、高いパフォーマンスを持つ非同期処理（Async/Await）に特化したFastAPIをAI処理のコアとして使用します。 |
| ORM | SQLAlchemy (with Pydantic integration) | FastAPI側でDB接続が必要な高度なロジックがある場合に備える。ただし、メインのメタデータはFirestoreを利用。 |

### 1.3 インフラストラクチャ・AI環境 (Infrastructure / AI Environment)
| 項目 | 技術名 | 目的・選定理由 |
| :--- | :--- | :--- |
| プラットフォーム | Google Cloud Platform (GCP) + Firebase | モバイルアプリのバックエンドとしての安定性、スケーラビリティ、AI処理に適したGPUリソースの提供。 |
| 認証 | Firebase Authentication | ログイン、新規登録、メール/パスワード変更といったユーザー認証機能を提供。Flutterクライアントと容易に連携可能。 |
| データベース | Cloud Firestore | ユーザーデータ、認証情報、楽曲メタデータ（感情タグ、プロンプト、いいね、再生回数など）の永続化。モバイルクライアントへのリアルタイムデータ同期（フィード更新など）に強み。 |
| ストレージ | Cloud Storage for Firebase | 生成された**楽曲ファイル（例: MP3, WAV）**の保存と、高速な配信。データベースに直接楽曲ファイルを保存しない。 |
| AI生成エンジン | 外部API (Google Gemini APIでプロンプト修正・英語に翻訳し、beatoven.aiで曲作成) | 感情/プロンプト/ジャンルに基づき、音楽データを生成するコアエンジン。 |
| 非同期処理/AI実行環境 | Cloud Functions for Firebase (Python) | 時間のかかる楽曲生成リクエストのトリガーとして使用。FastAPIサーバー（GCP/AWSでホスト）の呼び出しや、Firestoreの変更検知トリガーとして利用する。 |
| ホスティング | Firebase Hosting | もしWeb版やランディングページが必要になった場合のホスティング。 |
